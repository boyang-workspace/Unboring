## What was done

### 1. Surprise me! no longer shuffles card order

- **File:** `assets/app.js:553`
- **Change:** Removed the shuffle logic from the Surprise button handler. Now only applies random theme randomization — preserves user's custom card layout after drag repositioning.
- **Why:** Previously, clicking Surprise would both randomize styles AND reorder cards, defeating the purpose of iOS-widget-style drag-to-reposition.
- **How to test:** Drag cards to rearrange, click Surprise — cards stay in their positions, only colors/fonts change.

### 2. Systemic card bottom-padding fix

- **Files:**
  - `assets/style.css:104` — `.cn-card` now has `padding-bottom: 16px`
  - `assets/components.css:7` — `.cn-card-footer` margin-bottom changed from `-1px` to `calc(-16px - var(--bw))`
- **Why:** Many cards had content flush against the card bottom edge (especially #53, #50, #55, #62). Adding a systemic 16px bottom padding to all cards eliminates the need for per-card `:last-child` or `margin-bottom` hacks.
- **Note:** Footer margin is negative to compensate for the card padding, keeping it visually flush with the card bottom edge.

### 3. Full-bleed hero cards: removed conflicting padding

- **Files:** `index.html` (lines 107, 187, 243) and `canvas/index.html`
- **Change:** Added `style="padding:0"` to cards #37 (`cn-hero-dark`), #28 (`cn-hero-dark`), #79 (`cn-hero-gradient`).
- **Why:** These cards have hero components with their own background color and border-radius. The global `padding-top: 16px` created a visible strip of default card background between the card border and the hero's colored background.
- **How these cards look now:** Hero background fills the card edge-to-edge. The hero components already have their own internal padding (24-28px).

### 4. #24 Testimonial double-spacing fix

- **File:** `index.html`
- **Change:** Wrapped the two testimonials (separated by `.cn-sep`) in a `.cn-card-content` div.
- **Why:** Both `.cn-testimonial` had `padding: 20px 16px` and the card had `gap: 16px`. The `gap` property only applies between flex children, and both testimonials were direct flex children. Adding `.cn-card-content` as a single wrapper removes the gap between them, while the `.cn-sep` separator's `margin: 0 16px` keeps clean spacing.
- **Before:** ~73px spacing between the two testimonials (20px padding + 16px gap + 20px padding + sep margins).
- **After:** 20px + 16px (sep margin) + 20px = 56px, plus the sep's own space.

### 5. Tag hover bridge

- **Files:**
  - `assets/app.js` — per-card `mouseenter`/`mouseleave` handlers with 100ms delay
  - `assets/style.css` — `.cn-card-tag.hover` selector
- **Change:** When moving the mouse from a card to its tag (positioned above the card), the tag would flicker and disappear. Added a JavaScript hover bridge: card mouseenter shows tag, mouseleave starts a 100ms timer. Tag `mouseenter` cancels the timer and keeps the tag visible. Tag `mouseleave` starts another 100ms timer. Only hides the tag when neither card nor tag is hovered.
- **How it works:** The `.hover` class toggles on `.cn-card-tag` via JS. CSS uses `.cn-card-tag.hover` as the visibility trigger alongside the existing `.cn-card:hover .cn-card-tag` rule.

## Things to know

- `index.html` is the main page (flat grid, 80 cards with `.cn-card-tag`). The build script at `scripts/build.js` generates flat-grid HTML but is NOT automatically run — `index.html` is hand-maintained.
- Canvas init position: `panX = 0; panY = 0` (top-left).
- Canvas mousedown checks `e.target.closest('.cn-card')` — returns early to prevent pan from interfering with card drag.
- Drag API: HTML5 native drag (`draggable="true"`), event delegation on `.grid`, `insertBefore` reorder (like iOS widgets).
- Width toggle: changes `data-width` attribute; CSS `[data-width="2"] { grid-column: span 2; }` handles the visual.
- Cards with `style="padding:0"`: currently #68, #35, #37, #28, #79. If adding new hero-style cards, check whether they need this too.
- Card `padding-bottom: 16px` is systemic — any card that needs full-bleed bottom content needs `padding:0` or individual handling.
