Drawer

Reveal secondary detail or editing context from the page edge.

Surfaces sheet shadcn/ui sheet
AI Prompt
Create a Drawer component for an AI-generated interface using shadcn-style composition. Use shadcn/ui sheet as the implementation base. The component should support default, muted, outline, ghost, destructive variants and default, open, hover, focus-visible, disabled states. Include clear anatomy for Root, Handle, Header, Content, Action area. Keep the visual language black, white, and gray with subtle borders, practical spacing, accessible focus states, and no decorative noise.
Negative Prompt
Do not invent a custom component API when shadcn/ui sheet already covers the base behavior. Avoid random gradients, oversized radii, unclear disabled states, missing labels, icon-only controls without accessible names, and variants that change layout unexpectedly.
Implementation Notes
Base: shadcn/ui sheet
Primitive: Radix Dialog
Tailwind: Use shadcn tokens for background, border, ring, muted text, radius, and state variants. Keep component-specific classes local and copyable.
Dependency: Use Radix Dialog through the matching shadcn component when possible.

Usage notes

Short guidance for humans and AI tools before copying the component.

Drawer helps teams reveal secondary detail or editing context from the page edge. It should feel like a reusable product primitive, not a one-off decoration.

Start from shadcn/ui sheet. Use Radix Dialog through the matching shadcn component when possible. Keep variants token-driven and keep states predictable.

Do not invent a custom component API when shadcn/ui sheet already covers the base behavior. Avoid random gradients, oversized radii, unclear disabled states, missing labels, icon-only controls without accessible names, and variants that change layout unexpectedly.
